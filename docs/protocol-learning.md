## OSI 模型与协议分层

网络协议按照 OSI 模型分为 7 层，本项目实现了以下关键层：

### 第 2 层：数据链路层
- **以太网（Ethernet）**：局域网通信的基础协议
- **ARP**：地址解析协议，将 IP 地址映射为 MAC 地址

### 第 3 层：网络层
- **IPv4**：互联网协议版本 4，提供逻辑寻址和路由
- **IPv6**：互联网协议版本 6，解决 IPv4 地址耗尽问题
- **ICMP**：互联网控制消息协议，用于网络诊断（ping/traceroute）

### 第 4 层：传输层
- **TCP**：传输控制协议，提供可靠的、面向连接的字节流服务
- **UDP**：用户数据报协议，提供简单的、无连接的数据报服务

### 第 7 层：应用层
- **HTTP**：超文本传输协议，Web 应用的基础
- **DNS**：域名系统，将域名解析为 IP 地址
- **QUIC**：基于 UDP 的现代传输协议，HTTP/3 的基础

## 协议定义文件概览

### 主要文件

1. **`eng_lib/headers.pkt`** — 包含所有主要协议的完整定义
   - 链路层：`eth`、`arp`
   - 网络层：`ipv4`、`ipv6`、`icmp`
   - 传输层：`tcp`、`udp`
   - 应用层：`http`、`dns`

2. **`eng_lib/quic.pkt`** — QUIC 协议实现
   - `quic_initial`：QUIC 握手初始包
   - `quic_short`：QUIC 数据传输短头包
   - `quic_crypto`：CRYPTO 帧（用于 TLS 握手）

3. **`eng_lib/bytes.pkt`** — 字节构建工具函数
   - 地址转换：`ip4`、`ip6`、`mac`
   - DNS 工具：`dns_name`
   - 层标注：`eth_bytes`、`ipv4_bytes` 等

4. **`eng_lib/net.pkt`** — 组合层函数
   - `net4`：IPv4 + 以太网组合
   - `net6`：IPv6 + 以太网组合

## 协议详解

### 以太网（Ethernet）

**位置**：`eng_lib/headers.pkt` 第 35-37 行

**协议概述**：
- IEEE 802.3 标准，局域网通信的基础
- 使用 MAC 地址（48位）标识设备
- 帧结构：目标MAC(6B) + 源MAC(6B) + 类型(2B) + 数据 + CRC

**关键字段**：
- `dst_mac`：目标 MAC 地址（广播=ff:ff:ff:ff:ff:ff）
- `src_mac`：源 MAC 地址
- `ethertype`：上层协议类型（0x0800=IPv4, 0x0806=ARP, 0x86DD=IPv6）

**学习要点**：
- MAC 地址的格式和作用
- 以太网帧的封装过程
- ARP 协议如何将 IP 解析为 MAC

### ARP（地址解析协议）

**位置**：`eng_lib/headers.pkt` 第 47-57 行

**协议概述**：
- RFC 826 标准
- 将网络层地址（IPv4）解析为链路层地址（MAC）
- 工作流程：广播请求 → 单播应答

**关键字段**：
- `htype`：硬件类型（1=以太网）
- `ptype`：协议类型（0x0800=IPv4）
- `op`：操作码（1=请求, 2=应答）
- `sha/spa`：发送方 MAC/IP
- `tha/tpa`：目标 MAC/IP

**学习要点**：
- ARP 的工作原理和报文格式
- ARP 缓存的作用
- ARP 欺骗攻击的原理

### IPv4（互联网协议版本 4）

**位置**：`eng_lib/headers.pkt` 第 62-82 行

**协议概述**：
- RFC 791 标准
- 提供逻辑寻址和路由功能
- 头部长度可变（20-60字节）

**关键字段**：
- `version`：IP 版本（4位，固定值4）
- `ihl`：头部长度（4位，单位4字节）
- `ttl`：生存时间（防止环路）
- `proto`：上层协议号（1=ICMP, 6=TCP, 17=UDP）
- `src/dst`：源/目标 IP 地址

**学习要点**：
- IP 地址的分类和子网划分
- IP 分片和重组过程
- TTL 的作用和 traceroute 原理

### IPv6（互联网协议版本 6）

**位置**：`eng_lib/headers.pkt` 第 111-121 行

**协议概述**：
- RFC 2460 标准
- 128位地址空间，解决 IPv4 地址耗尽
- 简化头部，提高处理效率

**关键字段**：
- `src/dst`：源/目标 IPv6 地址（128位）
- `hop_limit`：跳数限制（等同于 IPv4 的 TTL）
- `next_header`：下一个头部类型

**学习要点**：
- IPv6 地址的表示方法
- IPv6 与 IPv4 的主要区别
- IPv6 过渡技术

### ICMP（互联网控制消息协议）

**位置**：`eng_lib/headers.pkt` 第 156-166 行

**协议概述**：
- RFC 792 标准
- 用于网络诊断和错误报告
- ping 和 traceroute 的基础

**关键字段**：
- `type`：消息类型（8=请求, 0=应答, 11=超时）
- `code`：消息代码（细分类型含义）
- `id/seq`：标识符和序列号（匹配请求/应答）

**学习要点**：
- ICMP 消息类型的含义
- ping 命令的工作原理
- traceroute 的实现原理

### TCP（传输控制协议）

**位置**：`eng_lib/headers.pkt` 第 180-200 行

**协议概述**：
- RFC 793 标准
- 可靠的、面向连接的字节流服务
- 流量控制和拥塞控制机制

**关键字段**：
- `sport/dport`：源/目标端口号
- `seq/ack`：序列号/确认号
- `flags`：控制标志（SYN/ACK/FIN/RST）
- `window`：接收窗口大小

**学习要点**：
- 三次握手和四次挥手过程
- TCP 的可靠传输机制
- 流量控制和拥塞控制算法

### UDP（用户数据报协议）

**位置**：`eng_lib/headers.pkt` 第 224-234 行

**协议概述**：
- RFC 768 标准
- 简单的、无连接的数据报服务
- 头部开销小（8字节）

**关键字段**：
- `sport/dport`：源/目标端口号
- `length`：UDP 数据报长度
- `checksum`：校验和（可选）

**学习要点**：
- UDP 与 TCP 的区别和适用场景
- UDP 的不可靠性及其影响
- UDP 应用的常见模式

### HTTP（超文本传输协议）

**位置**：`eng_lib/headers.pkt` 第 258-280 行

**协议概述**：
- RFC 2616 标准
- 无状态的应用层协议
- 请求/响应模式

**关键字段**：
- `start_line`：请求行或状态行
- `headers`：头部字段列表
- `body`：请求/响应体

**学习要点**：
- HTTP 请求和响应的格式
- 常见 HTTP 方法和状态码
- HTTP 头部字段的作用

### DNS（域名系统）

**位置**：`eng_lib/headers.pkt` 第 310-340 行

**协议概述**：
- RFC 1035 标准
- 将域名解析为 IP 地址
- 分布式数据库系统

**关键字段**：
- `id`：事务 ID
- `flags`：标志位（QR/Opcode/RD/RA 等）
- `questions`：查询记录
- `answers`：应答记录

**学习要点**：
- DNS 的查询和应答过程
- DNS 记录类型（A/AAAA/CNAME/MX 等）
- DNS 缓存和递归查询

### QUIC（基于 UDP 的传输协议）

**位置**：`eng_lib/quic.pkt` 第 32-46 行

**协议概述**：
- RFC 9000 标准
- Google 开发，HTTP/3 的基础
- 基于 UDP，内置加密，多路复用

**关键字段**：
- `pnl`：包号长度位
- `pn`：包号
- `dcid/scid`：目标/源连接 ID
- `payload`：帧数据

**学习要点**：
- QUIC 与 TCP 的区别
- QUIC 的连接迁移特性
- QUIC 的 0-RTT 握手

## 学习路径

### 初级阶段：理解基础协议
1. 从以太网开始，理解数据链路层的作用
2. 学习 IP 协议，理解网络层的寻址和路由
3. 学习 TCP/UDP，理解传输层的服务类型

### 中级阶段：深入协议细节
1. 分析 ICMP，理解网络诊断的原理
2. 学习 DNS，理解域名解析过程
3. 研究 HTTP，理解 Web 应用的通信

### 高级阶段：现代协议和优化
1. 学习 QUIC，了解现代传输协议的设计
2. 分析协议头部的优化技术
3. 研究协议安全性和加密机制

## 实践建议

### 1. 使用 prping 工具观察协议

```bash
# 查看以太网帧结构
prping engine --ls headers.pkt eth

# 查看 TCP 头部
prping engine --ls headers.pkt tcp

# 查看完整的 HTTP 请求
prping engine --hex headers.pkt http

# 实际发送 ICMP ping
prping ping 8.8.8.8

# 实际发送 TCP ping
prping ping 8.8.8.8:80

# 实际发送 UDP ping
prping ping -u 8.8.8.8:53
```

### 2. 分析网络流量

```bash
# 使用 prping 捕获和解析网络流量
prping packet --raw headers.pkt

# 查看 QUIC 协议结构
prping engine --ls quic.pkt
```

### 3. 修改协议定义进行实验

```bash
# 修改 headers.pkt 中的协议定义
# 例如：修改默认 TTL 值，观察网络行为变化
# 例如：添加新的协议字段，理解协议扩展机制
```

### 4. 阅读协议注释

每个 proto 函数都包含详细的中文注释，包括：
- 协议的 RFC 标准引用
- 协议的工作原理和特点
- 每个字段的含义和取值范围
- 引擎自动计算的字段说明

## 总结

通过分析 `eng_lib/` 目录中的协议定义文件，你可以：

1. **理解网络协议的分层结构**：从链路层到应用层
2. **掌握协议头部的格式**：每个字段的含义和作用
3. **学习协议的工作原理**：连接建立、数据传输、错误处理
4. **了解现代协议的设计**：QUIC 等新协议的创新点

本项目提供的协议定义是完整的、可执行的代码，不仅可以学习理论知识，还可以通过实际运行来验证理解。建议结合网络抓包工具（如 Wireshark）一起学习，效果更佳。
